# Validation record

Verified on November 10, 2026 with Expo SDK 58, React Native 0.88.1 and Xcode 27.2.

| Environment | Evidence |
|---|---|
| Clean checkout | Installed dependencies with `npm ci`, then ran TypeScript, ESLint and the state tests successfully. |
| JavaScript | Six store tests cover edit, enable, disable, delete, failed mutations, persisted preferences, immediate Stop, initial-load retry, and foreground reconciliation. Both production Metro bundles exported to Hermes bytecode. Expo's dependency version check passed. |
| Swift | Eight assertions on the production recurrence function passed, including spring gaps, fall folds, a half-hour DST transition, selected weekdays, and time zones. |
| Android instrumented tests | Two device tests on API 35 exercised real native records and AlarmManager entries for editing, enabling, disabling, deleting, rejecting stale deliveries and preserving repeat schedules. |
| Kotlin | Six JUnit tests on the production recurrence function passed. They cover one-shot rollover, selected weekdays, exact-minute boundaries, full- and half-hour DST transitions, and time zones. |
| iOS app build | The Release configuration built in Xcode 27.2, installed and launched on the iPhone 17 simulator running iOS 26.5. The bundle contains the production Hermes bytecode and all three custom alarm sounds. |
| iOS app interaction | XCUITest granted AlarmKit access, created a 07:00 Monday/Thursday alarm, edited the weekdays, toggled it, relaunched the app, changed appearance and deleted the alarm. A separate one-time alarm set through the picker for 18:12 entered the ringing screen after process termination. The app offered Stop Alarm, and pressing it left the one-shot disabled. The [bridge regression](../tests/ios-ui/README.md) checks native save and read-back on an installed release. |
| iOS native integration | An XCTest host linked the production Swift engine on an iPhone 17 simulator running iOS 26.5. The daemon registered and fired both one-time and weekly alarms after the host was terminated. Relaunch exposed the ringing IDs. Native Stop disabled the one-shot and preserved the weekly schedule. |
| Android app build | Expo SDK 58 and Gradle 9.4.1 produced a standalone arm64 Release APK using Android SDK 37. Its manifest targets API 36 with a minimum of API 26. APK Signature Scheme v2 verification passed using the local QA signing key. The packaged APK contains the bundled JavaScript and native libraries. |
| Android app interaction | On an offline Android 15 emulator, the installed APK requested notifications and saved a named Ripple alarm from the Android time picker. With the process killed and device locked, Android started a new process at 18:28 and showed the native ringing screen. Stop ended the foreground service. On relaunch the one-time alarm was disabled. A weekly alarm survived a PIN-protected reboot and appeared in the selected dark theme at 18:32 before the first unlock. Stop preserved the following Tuesday’s 18:32 registration. |
| Android native integration | On an Android 15 emulator, a native test host registered simultaneous one-time and weekly alarms. After process termination and screen lock the receiver started the ringing activity. Stop advanced to the other alarm, then ended the service. The one-shot was disabled and the weekly alarm retained its next occurrence. A separate run verified rescheduling after a PIN-protected reboot, delivery and Stop before first unlock, and mid-ring notification revocation. |

On the iOS simulator, SpringBoard crashed in ToneLibrary during alarm sound playback. The test confirmed AlarmKit's alerting state and the app's native Stop command. Physical lock-screen controls, speaker output, Focus, silent mode, reboot, battery policies and vendor-specific variations require the [real-device checklist](device-checklist.md).

The hosted Android QA workflow was dispatched. GitHub withheld the runner due to the account billing or spending limit, before any build step ran. [Workflow run](https://github.com/jouleka/Wupiko/actions/runs/42857927046)

Expo Doctor passed all 20 checks on the final run, including the app configuration schema, React Native Directory validation and SDK dependency versions. GitHub flagged two moderate advisories in the Expo tooling dependencies `glob` and `minimatch`. The installed versions come from Expo CLI, Expo fingerprinting and ESLint. The npm audit found zero high or critical advisories. Its suggested Expo change would downgrade the SDK. [Repository dependency alerts](https://github.com/jouleka/Wupiko/security/dependabot)
